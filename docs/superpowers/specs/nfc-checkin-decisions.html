The part that gets better

Because our own app reads the tag, the sticker no longer has to hold a web address. It can hold a meaningless string instead. Someone tapping it with a generic NFC reader app sees gibberish rather than a working link they could save and use from home — which closes the biggest hole in the earlier design, and means plain pennies-each stickers are fine.

Student flow

Four steps, nobody waiting on anybody

Numbered because it genuinely is a sequence — each step depends on the one before it. No lecturer has to press anything for a student to check in.

01 Student

Touches the sticker

App already open and signed in. The button arms for sixty seconds, then greys out again — long enough to press, too short to walk anywhere.

02 Student

Presses Check in

The app sends the tag's secret and nothing else. No email, no password, no location.

03 Server

Finds the lecture

Today's sessions on units they're enrolled on, whose start–end window contains this minute. Two running at once and the app asks which.

04 Server

Saves it, with the time

P, or L past the late threshold, stamped 09:07. Written immediately — nothing waits for approval.

The window is the lecture itself

Taps are accepted from the moment a lecture starts until the moment it ends, and at no other time. A student tapping at 08:52 for a nine o'clock class is refused; so is one tapping at 12:15 for a class that finished at noon. There is no button for a lecturer to press and nothing to remember to switch off — the timetable already knows when the class is.

One consequence worth deciding on now. Strictly “not before” means a student standing outside the door at 08:58 is turned away, which will be reported as a bug in the first week. So there is a setting for it — minutes of grace before the start — and it ships at zero, which is the rule as you asked for it. Changing it later is a config edit, not a deploy.

Why “not tapped” is not “absent”

Nothing is written for those five students until the lecturer says so, and the button says exactly how many it is about to affect. That press is the only route from this feature to an A, and a named human is on the end of it.

Automatic absence would turn a flat battery, a forgotten phone, or a handset with no NFC into a permanent academic record — most often for the students least able to argue about it. An untaken register already means absence, and the attendance maths leaves unmarked sessions out of the denominator on purpose.

Decision one · researched 28 Aug 2026

Which NFC plugin

There is no official Capacitor NFC plugin, so this is the one genuinely new dependency. Three real candidates, and the answer is not the one I would have guessed.

Plugin Licence Latest Cost Verdict
@capgo/capacitor-nfc MPL‑2.0 8.2.5 · 20 Aug 2026 Free Use this
Capawesome NFC Insiders licence Actively maintained $99/mo, or $1,980 once Only if capgo fails
capacitor-nfc (Exxili) MIT 0.1.5 · Apr 2022 Free Abandoned

Capgo is the clear pick, and the version numbers are why. It declares @capacitor/core >=8.0.0 and this client runs Capacitor ^8.4.2 — a real match, not a hopeful one. It was published eight days ago, and on Android it uses NfcAdapter.enableReaderMode, which is exactly the silent API the flow above depends on.

MPL‑2.0 is weak copyleft and file-scoped: you may ship it inside a closed app without publishing your own source. Only changes to the plugin's own files would have to go back, and installing it and calling it never triggers that.

The Exxili plugin is the one most search results surface first, and it is four years stale — last published April 2022, against Capacitor 3. It would not build. Capawesome's is good and well documented, but it moved behind a paid subscription, and there is no reason to pay when the free one matches our Capacitor version.

College Wi‑Fi, by IP They are on the college network Building, not room. Breaks if the ISP renumbers Nothing Open — see below
GPS geofence Roughly which building, at best 20–100m indoors; mock location is a settings toggle A privacy conversation Out
Bluetooth beacons Genuinely which room Cheap ones broadcast a fixed ID anyone can clone Per room, plus batteries Out for now

On Wi-Fi, the usual idea does not work but a better one does. An app can read the network name only with extra permissions, and a web page cannot read it at all. What works instead is checking the address the request arrives from: on college Wi-Fi it exits through the college's gateway, at home it does not. The server observes that rather than the phone reporting it, so the phone cannot lie about it — and app.set("trust proxy", 1) is already set in server/src/index.js, so req.ip is the student's real address today, with nothing to fix first.

Two caveats before committing. The college needs a static public address per site — HOME_SITES lists HND, FE and SL, so possibly three connections — and online sessions must be exempt, or the check locks out precisely the students it was never aimed at.

Decision three

Recording the minute, without losing it later

You asked for the time to be saved, and there is already a column that looks like the answer. It is not. AttendanceMark.takenAt is reset on every update — routes/hnd.js writes takenAt: new Date() each time a register is saved. It means when this mark was last edited, not when the student arrived. A lecturer correcting the register at four o'clock silently destroys the 09:07 tap, which is exactly the figure you would want at an appeal.

So it needs its own column, written once and never touched again:

// When the student actually tapped in. NULL when nobody self-checked-in —
// the lecturer marked them by hand — which is "not measurable", not an
// early arrival. Written ONCE. A later register save must not overwrite it:
// takenAt already records when the mark was last edited, and conflating the
// two loses the only record of when the student was in the room.
checkedInAt  String?   // "HH:MM", London, via clock.localTime()

A string, not a timestamp. It matches CheckIn.timeIn, which this codebase already stores as HH:MM and renders verbatim, and the session carries the date so the two reconstruct the instant exactly. More to the point it avoids a trap this project has already fallen into: STATUS.md records the 08:00 notifications firing at 09:00 through British Summer Time because something read the host clock. A time written through localTime() is right when stored and stays right; a timestamp has to be re-zoned correctly at every render, forever.

Not in scope

Things I would not build

Tapping out

The first check-out is final, deliberately, so a stale tab cannot rewrite how long somebody was on site. A tag by the door that a member of staff walks past twice would break that quietly.

Card readers at the door

They record building entry, not class attendance. A student who taps in at nine and goes to the café is present in your data and absent in fact — hardware bought to get a worse answer than a lecturer glancing round the room.

Face or fingerprint recognition

Special category data under UK GDPR. It needs a DPIA, and proportionality is very hard to argue for attendance when a lecturer with a screen achieves the same thing. The ICO has pushed back on schools using it for less consequential purposes than this.

Overwriting a lecturer's mark

A tap never changes a mark that already exists. This inherits the Moodle importer's invariant for the same reason: where two sources disagree, the human who was in the room wins.

Staff who tap in and choose “Online”

Minutes of grace before a lecture starts

Zero is the rule as you gave it and the safest default. Five is what stops the first week's complaints from students standing outside a locked door at 08:58.

Students whose phone has no NFC

Some budget Android handsets, and any iPhone older than the 7. They can never use this. A camera scan of a code printed on the same sticker covers them, but it needs a second plugin and a second code path.

Lecturer marks them, as now Build the camera fallback too

Which comes first — this, or the missing registers?

Everything here hardens attendance that gets recorded. None of it touches sessions where no register was taken at all, where the maths quietly excludes them and nobody's percentage moves. That is the failure that costs you at a funding or visa audit. It is already counted in routes/hnd.js as registersDue, buried in one lecturer's profile screen, and surfacing it is the smallest build on this whole page.
